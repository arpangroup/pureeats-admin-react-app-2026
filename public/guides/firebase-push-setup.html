PureEats Admin · Setup Guide

Firebase Push Notifications

Everything you need to wire up Firebase Cloud Messaging (FCM) for the customer web app and this admin panel — from creating the Firebase project to sending your first test notification.

1. Create the Firebase project & web app

Firebase Console

1

Create a Firebase project

Go to the Firebase Console, click Add project, and follow the prompts. Google Analytics is optional.

2

Register a Web app

Inside your project, click the </> (Web) icon on the project overview page to register a new web app. Give it a nickname (e.g. "PureEats Customer App").

3

Copy the Firebase config

Firebase shows a config object like this — copy every value, you'll need them shortly:

const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
4

Enable Cloud Messaging & generate a VAPID key

Go to Project settings → Cloud Messaging. Under Web configuration, click Generate key pair to get your VAPID key (needed for browser push permission requests).

5

Paste everything into the admin panel

Back in PureEats Admin → Settings → Push Notifications, fill in the Firebase Cloud Messaging panel with the API key, Auth domain, Project ID, Storage bucket, Messaging sender ID, App ID and VAPID key from steps 3–4, then Save.

2. Enable server-side push (Firebase Admin SDK)

Backend Required for this admin panel's "Send test notification" button and any real order-update push to actually reach a device.

1

Generate a service account key

In the Firebase Console, go to Project settings → Service accounts, then click Generate new private key. This downloads a JSON file — keep it secret, never commit it to source control.

2

Point the backend at it

Save the JSON file somewhere on the machine running the PureEats backend, then set its absolute path as an environment variable before starting the app:

FCM_CREDENTIALS_PATH=/absolute/path/to/service-account.json

Until this is set, the backend logs push notifications instead of actually sending them (safe no-op mode) — nothing breaks, but devices won't receive anything.

3. Wire up the customer web app

React app

1

Add a service worker

Create public/firebase-messaging-sw.js in the customer React app so notifications can be received while the tab is in the background:

importScripts("https://www.gstatic.com/firebasejs/10.x.x/firebase-app-compat.js");
importScripts("https://www.gstatic.com/firebasejs/10.x.x/firebase-messaging-compat.js");

firebase.initializeApp({ /* same config as above */ });
firebase.messaging();
2

Request permission & get a device token

On the client, call Notification.requestPermission(), then getToken() from the Firebase Messaging SDK, and send that token to POST /api/v1/notifications/push-token so the backend can target this device.

3

Send yourself a test notification

Once a device token is registered, go to Settings → Push Notifications in this admin panel and use the Send test notification button with your user ID to confirm everything end-to-end.
